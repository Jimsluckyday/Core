Exactly what each button does & why this order ▾

1. Find & Update Pick Info — run this FIRST, always. It checks every sport on that date at once (no sport filter, unlike the other three) and fills in Start Time and Home/Away — never Prop Team or Tournament, that's exclusively step 2. This is also the tool that catches a pick entered on the wrong calendar day (KBO/Tennis-style late-night games that land a day early or late in your local time) — it flags those instead of guessing, so you fix the date before doing any other work on that pick, rather than after.

2. Find & Update Teams / Tournaments — run this second, once you're confident every pick's date is actually correct. It looks up and fills in Prop team for MLB/NBA/WNBA/NHL Player Props, and Event name/tournament for Tennis/Soccer, for picks currently missing them on that date — the sole owner of both fields. Golf is not covered yet — no schedule source exists for it.

3. Find Missing Odds — run this third, once matchups/tournaments are filled in. Never calls a live odds source (no paid odds API is wired in yet, same as the rest of this box being test data until one is) — it only finds and sorts picks still missing an opening or closing price on that date. Straight Moneyline picks (never period-qualified variants like "Moneyline First5", those move far less) come back separately, flagged as needing a real researched number — a flat default price is never safe for a market that can swing hundreds of points between a favorite and an underdog. Everything else is flagged as safe for Bulk-fill Standard Odds or Bulk-match Odds in Data Tools instead of a one-by-one manual price.

4. Find & Update Results checks final scores and grades Moneyline/Spread/Total picks for every sport on that date — Player Props and other custom bet types are never auto-graded, on purpose. Covers MLB, NHL, NBA, NFL, WNBA, NCAA Football/Basketball/Baseball, and CFL — also grades straight MMA (UFC) Moneyline picks, winner-take-all only, matched by fighter name against that day's real card (method/round/other MMA bet types still need manual grading). Tennis, Soccer, Golf, Cricket, KBO, CBA, and Euro Basketball have no ESPN scoreboard mapping and are skipped here; those still need the legacy TheRundown-based Grade Results in Old Tools (or manual research) if they need automated grading at all.

5. Find & Update Golf Results is separate from step 4 — it grades the 3 golf-specific Player Prop stats ("Round Matchup", "Tournament Matchup", "Tournament Winner") using ESPN's real PGA Tour leaderboard, since Player Props are never touched by the Moneyline/Spread/Total grader. LPGA/Champions/Korn Ferry/European Tour picks aren't covered yet (PGA Tour only) and will come back unmatched with a clear reason rather than a wrong grade.

Capper streak history — internal, not public

Every consecutive run of wins or losses in a capper's graded history, not just whichever one is currently active -- so "on a 7-game win streak right now" doesn't hide that they also had an 11-game streak earlier, which matters for judging whether a capper runs hot/cold in bursts. Pushes are skipped over entirely (neither break nor extend a streak). Ordered by event_date, which is when the game actually happened, not when the pick was entered -- important since backfilled historical data isn't always entered in chronological order.

All-time streak leaderboard

The longest win streaks and longest losing streaks across every capper, all time -- for spotting genuinely epic runs either direction, not just what's active right now.

Capper performance by bet type — internal, not public

Each row is one capper's record within a single bet type (e.g. "King Cap · Spread"), not their overall record — so a capper who's mediocre overall can still show up strong on one bet type. Sorted by win % within each qualifying row, same minimum-picks logic as the leaderboard. Pick type is a separate filter from bet type: "Straight only" hides the Parlay row for every capper, "Parlays only" shows just that row, and "Straight + Parlays" (default) shows both — sort or filter the Capper column to line a capper's straight bet-type rows up next to their Parlay row for a side-by-side comparison. Use this to decide which of a capper's bet types are actually worth publishing, rather than promoting or hiding a capper wholesale.

Pick tier performance — internal, not public

Breaks down every graded pick by tier — count, win-loss-push, and win % for Tier -1 (explicitly below base, e.g. a lotto pick) through Tier 4 (a capper's highest-confidence pick, however they brand it — Whale of the Day, Lock of the Week, VIP pick, etc.). Select "All cappers" to see an "all cappers combined" table first (e.g. "Tier 4 picks are 20 for 25 overall") — useful for judging whether a tier is a meaningful signal at all before deciding how much scoring weight to give it — followed by the same breakdown split out per capper, since cappers use tiers differently and one capper's Tier 4 may perform very differently than another's. The Straight/Parlay column shows how many of that tier's picks were standalone bets vs. whole parlays (a parlay's tier comes from what the capper called the whole combo, not guessed from its legs) — a further table below shows how the individual games inside those parlays did, since every leg shares its parlay's own tier.

Consensus picks — internal, not public yet

Publish ranking — internal, not public

The date range above filters on event_date (when the game actually happens), never date_entered (when the pick was posted). A pick entered today for a game two days from now will not appear until that later event date falls inside the range -- so this alone can't publish a pick before its game happens. Every card below also shows its own "Event:" date in the header so you can visually confirm before publishing. Scores every currently-pending pick using four equally-weighted signals (25% each): win % in this exact sport + bet type combo (e.g. Tennis Spreads specifically, not Spreads in general), overall win %, current streak (a bad streak actively drags the score down, not just withholds a bonus), and confluence — a bonus or PENALTY when other cappers independently picked this exact same game/selection/line. An agreeing capper above a 50% record helps the score; one below 50% actively hurts it, and the effect grows stronger both with a larger losing sample and with more agreeing cappers (capped at 3+). The sport+bet-type rate blends toward that capper's broader all-sport rate for that bet type until enough sport-specific picks pile up — so "2-0 in Tennis Spreads" leans on their overall Spread record at first, rather than either treating 2-0 as proven or ignoring it as meaningless. All win percentages are otherwise sample-size-adjusted the same way — a lucky small sample can't out-rank a proven track record. Click the small "N agreeing ▾" note under any score to see exactly which other cappers contributed to that pick's confluence bonus. Sort by Score to find the best candidates, then click Publish on however many you want featured. Include parlays as candidates is off by default -- a parlay is still a fundamentally weaker bet type in aggregate, so it stays out of the everyday list. Turn it on to go looking for the rare outlier: a capper's own track record specifically ON parlays (his real "Parlay" bet-type win %, e.g. "15-0 on 2-leg parlays") now scores exactly like any other bet type once this is checked. A parlay's overall win % stays excluded from his general record either way (same correlated-outcome reasoning as its legs) -- only its own bet-type-specific record counts. Its confluence is the average of each of ITS OWN legs' confluence (how much other cappers independently agree with each team in the combo), not a match on its own "N-Leg Parlay" label.

Publish performance — internal, not public

Every pick published since the score-tracking feature was added has its score snapshotted at the exact moment you clicked Publish — this compares that snapshot against the actual graded result, bucketed by score range, so you can see whether a high score has actually meant a higher win rate in practice, or whether the formula needs recalibrating. Only picks with both a score snapshot AND a final graded result (win/loss/push) count toward the win % — still-pending ones are shown separately, not counted either way yet. Picks published *before* score tracking existed have no snapshot to compare — they're listed in their own section at the bottom for completeness, but can't contribute to the win % analysis since there's nothing to check the outcome against.

Formula backtest — internal, not public

Recalculates what score EVERY graded pick would have gotten, using only the data that actually existed before that pick happened — not each capper's full current record, which would unfairly use information from the future. This is the real test of whether the formula works: if higher scores actually produced higher win rates historically, the weighting is doing its job; if the buckets come out flat, that's a sign the formula (or its weights) needs a second look. Also breaks down each of the four components on its own, so you can see which ones are actually predictive versus just adding noise.

Scorecard review — internal, not public

Every real pick from this date -- published or not -- re-scored using only the data that existed at the time (same point-in-time math as Formula Backtest above), sorted highest score to lowest. Each card shows the full breakdown (overall record, bet-type record, streak, tier, and consensus) plus exactly which other cappers agreed and their own records at the time, alongside the pick's actual result -- so a highly-rated pick that still lost, or one nobody agreed on that still won, is easy to spot at a glance. Parlay wrapper rows and individual legs aren't scored on their own here, same as everywhere else this formula runs -- a leg was never a standalone candidate to publish, though it still counts as evidence for whichever other cappers agreed with it.

Formula settings — internal, not public

⚠ This changes how the formula scores picks GOING FORWARD only. It can never affect anything already published — every published pick's score and Hot Pick status were permanently locked in the moment you clicked Publish, and nothing here can reach back and change that. The public-facing page also never runs this formula at all, so end users will never see any sign that a change was made. Even so: run a backtest first, only change one thing at a time, and confirm the change actually helps before trusting it.

High consensus badge threshold is the total agreeing-capper headcount (standalone + parlay legs, this pick included) needed to show the red "Consensus Pick" badge/tag on a card. Pin-to-top threshold is a separate, usually higher bar -- clearing it pins a second copy of that card in a callout above the #1 ranked pick on Publish Ranking, regardless of search/sort/filter, so a big pile-on can never get buried at a low rank without being seen. Neither of these touches the actual score or ranking in any way -- confluenceCapCappers above is the only thing that does that.
Smoothing (k) controls how fast a capper's win % is trusted as sample size grows — higher means more proof required before trusting a small sample. Streak cap is the longest streak that still adds extra weight beyond it (a 25-game streak scores the same as one right at the cap). Confluence cap is how many agreeing cappers it takes to reach full confluence weight. Hot Pick threshold is the win-streak length required to earn the public "Hot Pick" badge at the moment a pick is published. Parlay leg weight is how much an individual game inside a parlay counts everywhere in scoring, relative to a straight bet (100%) — his own overall/bet-type record, streak, and how much weight his agreement adds to another capper's confluence. A capper only bundling a game into a parlay (rather than calling it on its own) wasn't confident enough to call it standalone, so it's real evidence, just weaker evidence; a parlay's own bundled win/loss is never counted anywhere, since it's the same correlated outcome as its legs, and a parlay is never itself scored or published. Tier bonuses are the MAXIMUM points a pick can earn for the tier the capper marked it as (Tier 0 never gets a bonus) — the actual bonus is that maximum scaled by how good THIS SPECIFIC capper's own track record is within THAT SPECIFIC tier (not flat, and not the same for every capper). A capper who's 5-for-10 in his own Tier 2 picks gets roughly half the Tier 2 maximum; one who's genuinely strong there gets most of it; one with no Tier 2 history yet starts at half credit and moves from there as real results come in. Same sample-size smoothing as everything else applies, so even a perfect small sample never earns the full maximum. Tier -1 is for a pick the capper explicitly signaled as below his normal base confidence (a lotto pick, an explicitly smaller unit size than usual) -- same scaling logic, just typically expected to be a negative number once backtesting shows the pattern is real, since it's meant to actively hurt a score, not just withhold a bonus. Tier -1 confluence weight is separate from the bonus above and solves a different problem: the bonus only affects a Tier -1 pick's OWN score, it does nothing to stop a pile of low-confidence "lotto"/dartboard picks from several cappers inflating a game's confluence signal at full weight, same as if they were real standalone calls. This is how much a Tier -1 pick counts as "agreement" toward some OTHER capper's confluence bonus on the same game -- defaults to 25%, lower than Parlay leg weight (50%), since an explicit reduced-confidence signal is reasoned as weaker evidence than even a parlay leg call. Combines multiplicatively with Parlay leg weight if a pick is both (a Tier -1 parlay leg counts for less on both counts at once, not just whichever discount is larger). Each tier defaults to 0 (no effect) independently; check the Formula Backtest's tier breakdown first to see whether the real data actually supports setting a given tier away from 0, since one tier being worth adjusting doesn't mean they all are. Tier calibration is a completely separate signal from the tier bonuses above, and works even while every one of those stays at 0 -- a tier can look unremarkable in aggregate (e.g. Tier 3 sitting at 50% combined across everyone) while still hiding a real split underneath: one capper going 10-0 in his own Tier 3, another going 0-10 in his, roughly canceling out in the combined number. This compares each capper's OWN record at a tier against his OWN overall rate (not a flat 50%, and not the tier's combined rate either), so a capper who's genuinely better or worse AT a specific tier gets a real bonus or penalty for it, independent of whether that tier is worth anything as a blanket rule for every capper. Tier calibration minimum sample is a hard cutoff, not smoothing -- below this many picks at that exact tier for that exact capper, this returns zero, no partial credit. Defaults to 10: doesn't matter if he's called 50 or 500 picks overall, once his own sample at that one tier clears this number it's treated as a strong enough indicator to act on. Raise it if 10 turns out too low once real data comes in (check the Tier calibration points quartile section in Formula Backtest, which only appears once this weight is turned on).

Notable statistics — internal, not public yet

Scans every capper × tier, capper × bet type, and capper × sport/bet-type combo for a record notable enough to act on -- either promote (Travy going 10-0 on parlays) or watch closely (a real cold streak in one specific slice, not just an overall bad day). Ranked by a Wilson confidence bound, not raw win %, so a 2-0 record can never outrank a real 10-0 one -- it asks "how good is this, even in the worst plausible case given how few picks I've seen," which naturally demands more proof from a smaller sample. The minimum sample size is deliberately NOT a fixed number -- it's a percentage of the average capper's total graded volume, recomputed live every time this runs, so the bar rises on its own as your overall data grows instead of staying stuck at whatever felt right on day one (the absolute floor just prevents it from allowing something silly while the average itself is still tiny). This is a snapshot for you to look at and act on by hand -- nothing here feeds the scoring formula yet.

Capper trends — internal, not public yet

Shows each capper's win % across their last several weeks or months side by side, so a bad recent period can be read against their own history instead of in isolation -- "4-9 this month" reads completely differently next to "58% over the last year" than it does alone. "Trend" is the most recent qualifying period's win % minus that capper's all-time win % from everything BEFORE that period (same sport filter applied to both, if one is set) -- positive means recently better than their own history, negative means recently worse. ⚠ This blank-date sweep is also the correct way to catch Series Winner/Playoff Series Winner picks, and any long-term futures bet (e.g. "Blue Jays to win the World Series," placed in April at good odds, not decided until October). Bulk-fill standard odds — only fills what's missing, never overwrites a real researched value

Spread and Over/Under odds move far less than the straight Moneyline -- the standard price is almost always close to -110 regardless of matchup, and Player Props are usually close enough for testing purposes even though they vary a bit more. Period-qualified variants (Moneyline First5, Moneyline 1st Inning, etc.) behave the same low-variance way and are treated like any other bet type here -- only the full-game Moneyline swings wildly enough (a heavy favorite vs. an underdog can be hundreds of points apart) to need real research instead of a default. Rather than researching each low-variance pick individually, this fills in a standard price for any pick of the selected bet type(s) that's still missing odds, in bulk. Anything that already has a real value on file (from sync or research) is left completely untouched -- this only ever fills a blank, never replaces an existing number. "All bet types" never includes the straight Moneyline -- that market has no sensible universal default, so it's only ever touched by explicitly selecting it from the dropdown above, which shows its own separate warning.
⚠ Moneyline odds vary far more than any other bet type -- a heavy favorite might be -300 while an underdog is +250, so there's no sensible single default here the way there is for Spread/Totals/Props. Consider excluding Moneyline from this bulk-fill and researching those individually, or proceed only if you're comfortable with the real inaccuracy this could introduce.

Bulk-match odds — copies a pick's own known odds across, never a universal default

Distinct from "Bulk-fill standard odds" above -- that tool applies ONE default price you choose (e.g. -110) to picks missing odds entirely, and deliberately excludes Moneyline since there's no sensible universal default for it. This tool does something different: for any pick that already HAS a real, researched value on ONE side (opening or closing) but is missing the OTHER, it copies that pick's own value across to fill the gap -- never a guess, never a universal number, just this specific pick's own already-known odds mirrored onto the blank side. Because it's never inventing a value, every bet type is included, Moneyline too. A pick missing BOTH opening and closing is untouched here (nothing to copy from) -- use the bulk-fill tool above or research it individually for those.

Bulk mark parlay odds unavailable — parlays only, never guesses a price

CONFIRMED direct request 2026-08-22: "if we don't have parlay odds from the cappers... should just put -110 which is not ideal as there's huge variance... we have no way of legitimately validating these on old data." A parlay's combined price compounds with every leg, so a flat default (the way Bulk-fill Standard Odds handles Spread/Totals) would look confidently precise while being wildly wrong -- an 11-leg parlay is nowhere near -110. This tool never guesses a number at all: it marks matching picks odds_unavailable instead, the same flag already used everywhere else in this system to mean "confirmed we can't get a real value for this" -- it drops them out of profit/value math and stops them re-appearing as "missing" in every future check, without ever presenting a fabricated price as if it were real. Only ever touches the PARENT parlay pick (the "N-Leg Parlay" record itself) -- never individual legs, which structurally never carry their own odds regardless of whether the parlay's real price is known, so checking a leg's own fields was never a meaningful signal (confirmed directly: two real legs showed up here once, even though their parlay already had a real price on the parent). Non-parlay picks missing odds are a different situation entirely and aren't touched here. Only ever considers a parlay with BOTH opening AND closing odds blank -- if either side already has a real value, that's a Bulk-match Odds job instead, not this tool's.

Flagged lines — spot-check whenever you have time, never blocks anything

Two different, unrelated things share this list, each with its own badge below. Line flags are picks where research noticed a line that looked like a possible transcription error, not just normal line movement (which is expected and never flagged) -- grading already happened normally against the originally entered line regardless. Tier review flags are NOT an error of any kind -- they mark a brand-new capper's first pick, or an existing capper's first-ever use of a unit size/label, so you can confirm the estimated tier is right (the pick still uploaded and graded normally either way). Neither type blocks anything -- this is purely an optional later look, on your own time. Clearing a flag doesn't change anything else about the pick.

Missing data — find picks missing any field, regardless of grading status

⚠ Checkboxes below are ordered left to right on purpose -- work through them in order, don't jump to a color/warning you happen to notice. Start time, Parlay leg date mismatch, Schedule sync flagged, and Late-night pick come first because a wrong date is the root cause of most other "missing" results: fix the date before you research anything else, or you'll end up researching the wrong day's game and either come up empty or resolve a win/loss/push that didn't happen on that date. Event name and Prop team come next -- resolving those narrows what schedule-sync-backfill and Add Pick's Auto-fill button have to search. The remaining fields (Line, Home/Away, odds, Unit size) come last since they don't block other lookups. Not yet scored stays last on purpose -- run it as a final end-of-day check, not alongside the field checks above.
Checks EVERY pick regardless of result — a pick can already be graded win/loss/push and still be missing a field entirely, which matters just as much for published data integrity. Click "Only" next to any field to isolate to just that one, or "Select all" to check everything at once. Results open in the same sortable, filterable, inline-editable spreadsheet used for All Picks — sort or filter by any column, edit odds/tier/unit size/event name/start time directly in the table, or export to CSV for offline research (e.g. finding historical odds via Covers/Flashscore, or a game's actual start time).

Grading corrections — bulk-apply researched results back onto exact picks

Paste rows copied from a spreadsheet (or built in a chat) — first row must be column headers. Required: id only. Optional: result, event_date, event_name, line, opening_odds, closing_odds, line_flag, notes — only included columns get changed; anything left out is left alone. If result is included it must be exactly win, loss, or push, and marks the pick as manually graded — leave it blank entirely for an odds-only correction on a pick that's already graded (notes in that case are saved to the pick's own notes field instead, since grading wasn't touched). The line a capper gave us is always what we grade against, regardless of normal line movement between when the pick was sent and when it was researched — that's expected and never needs fixing. line should only ever be used for a genuine, obvious transcription error, and is rare; for the much more common "the line looks different than current research" situation, use line_flag (enter yes) instead — it doesn't change anything about the pick or hold up grading, it just adds it to the Flagged Lines list in Data Tools for an optional, unhurried look later. opening_odds / closing_odds are meant for a quick manual lookup (an AI chat search, Covers, Flashscore, or similar) when a pick's sport isn't covered by our own odds API, or historical odds are missing entirely — approximate is fine here, and if that pick is already published, this will correctly flow into the site's live win-rate and $100-per-bet totals the moment it's saved. Matching is by the exact pick id, never by name/date guessing, so there's no risk of updating the wrong pick.

Bulk import from spreadsheet

Paste rows copied from a spreadsheet (or built here in chat) — first row must be column headers. Required columns: date, capper, sport, bet type, selection. Optional: line, home_away, odds, prop_player, prop_stat (or just "stat"), prop_team, confidence, notes, published, parlay. For player props, if you don't include a separate prop_player column, the player's name is automatically taken from selection. prop_team is shown to customers alongside the player's name on the public page so casual fans don't have to look up who they play for — leave it blank if unknown, since it's not required for grading. parlay is a plain number (1, 2, 3…), your own local label for that capper's parlays that day — leave every standalone pick blank, and if the same selection belongs to more than one parlay, just paste it again on its own row with the other number rather than trying to combine numbers in one cell. The combined parlay summary row is created automatically from whichever rows share a number — you never type it yourself. Capper/sport/bet type must already exist in this tool (added via the Cappers/Sports/Bet Types section above) — unmatched names get flagged instead of guessed at.
